# Loopdash take-home: Pellbrook Garden Alliance homepage

Thanks for taking the time to do this. This exercise is how we see how you handle the whole job, not only the design part. It is a small, made-up client project, and you will do a slice of what the Junior Designer / Project Manager role does every week.

Budget about 3 to 4 hours. We mean it. Done and honest beats polished and late. If you run out of time, write down what you would have done next and stop.

## The setup

Pellbrook Garden Alliance is a fictional community garden nonprofit. Their homepage was built by a volunteer a few years ago and has problems. They want more volunteer sign-ups and more donations, and they want the site to work on phones.

Read these before you start:

- [BRIEF.md](BRIEF.md): who the client is, what they want, and the constraints.
- [CLIENT-EMAIL.md](CLIENT-EMAIL.md): an email from the client with some requests. Some are vague, some conflict with the brief, and one is a problem.

The site is plain HTML and CSS. There is no build step. Open `index.html` in a browser and it runs.

## What to do

**1. Improve the homepage.**
Fix what is broken and make it work for the client's goals. You decide what matters most. Figma mockups are welcome but optional. The HTML and CSS are the deliverable.

**2. Ship it the way we do.**
Fork this repo, make a branch, and commit as you go with clear messages. When you are done, open a pull request from your fork back to this repo. Fill in the PR template. Include before and after screenshots at desktop and mobile widths.

**3. Reply to the client.**
Write the email you would send Dana in response to [CLIENT-EMAIL.md](CLIENT-EMAIL.md). Confirm what you are doing, ask what you need to ask, and handle the request that does not fit. Put it in the PR description or in a file called `REPLY.md` in the repo root.

**4. Break down what is left.**
You will not finish everything in 3 to 4 hours. List the remaining work as tasks a developer could pick up without talking to you. Each task gets a short description, acceptance criteria, and a size (S, M, or L). Put them in priority order. This goes in the PR template.

**5. Say what you tested.**
A short QA checklist: which browsers, which screen sizes, what you checked for accessibility, which links you clicked. Also list anything you know is still broken. Honest beats complete.

**6. Tell us how you used AI.**
Use whatever tools you want. Claude, ChatGPT, Cursor, Copilot, Figma AI, MCP servers, anything. We use them daily and we want to see how you do. In the PR, say which tools you used, what for, and what you changed or rejected from what they gave you.

## Rules

- Timebox yourself to 3 to 4 hours. Note your actual time in the PR.
- Plain HTML and CSS. No frameworks, no build tools. A little vanilla JavaScript is fine.
- Do not add images beyond what is in `images/`. Editing those is fine.
- Keep it homepage only. Do not build other pages.
- Any AI tool is allowed. Any amount is allowed. You have to say what you used and own the result. If we ask you about a line in your PR, you should be able to explain it.
- Everything here is fictional. Do not look up or contact anyone.

## How to submit

1. Fork this repo.
2. Create a branch (something like `yourname/homepage-refresh`).
3. Commit as you go.
4. Open a pull request against this repo's `main` branch and fill in the template.
5. Send us the PR link using the email address in your invite.

If anything in the brief is unclear, make a reasonable call and say what you assumed. That is a normal part of the job.
