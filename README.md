# Loopdash take-home: Pellbrook Garden Alliance

Thanks for taking the time to do this. It is a slice of what the Junior Designer / Project Manager role does every week: a client emails, you figure out what they need, you do the work, you ship it, and you write back.

Budget about 3 to 4 hours. We mean it. Done and honest beats polished and late. If you run out of time, write down what you would have done next and stop.

## Start here

Open `index.html` in a browser. It is an email from the client. Their current site is attached (it is in the `site/` folder). Everything you need to know about the project is in that email and on that site. There is no other brief. Where the email is vague, make a call and say what you assumed. That is a normal part of the job.

Pellbrook Garden Alliance is fictional. So is Dana. Do not look anyone up or contact anyone.

## What to do

**1. Improve the homepage.**
Decide what the client actually needs from what they wrote, then fix the site in `site/`. You decide what matters most. Figma mockups are welcome but optional. The HTML and CSS are the deliverable.

**2. Ship it the way we do.**
Fork this repo, make a branch, and commit as you go with clear messages. When you are done, open a pull request from your fork back to this repo and fill in the template. Include before and after screenshots at desktop and mobile widths.

**3. Reply to the client.**
Write the email you would send Dana. Confirm what you are doing, ask what you need to ask, and handle anything that should not be done as asked. Put it in the PR description or in a file called `REPLY.md` in the repo root.

**4. Break down what is left.**
You will not finish everything in 3 to 4 hours. List the remaining work as tasks a developer could pick up without talking to you. Each task gets a short description, acceptance criteria, and a size (S, M, or L). Put them in priority order. This goes in the PR template.

**5. Say what you tested.**
A short QA checklist: which browsers, which screen sizes, what you checked for accessibility, which links you clicked. Also list anything you know is still broken. Honest beats complete.

**6. Tell us how you used AI.**
Use whatever tools you want. Claude, ChatGPT, Cursor, Copilot, Figma AI, MCP servers, anything. We use them daily and we want to see how you do. In the PR, say which tools you used, what for, and what you changed or rejected from what they gave you.

## Rules

- Timebox yourself to 3 to 4 hours. Note your actual time in the PR.
- Plain HTML and CSS. No frameworks, no build tools. The site has to keep running by opening `site/index.html`. A little vanilla JavaScript is fine.
- Homepage only. Do not build other pages.
- Do not add images beyond what is in `site/images/`. Editing those is fine.
- Leave `index.html` in the repo root alone. It is the email, not the site.
- Any AI tool is allowed, any amount. You have to say what you used and own the result. If we ask about a line in your PR, you should be able to explain it.

## How to submit

1. Fork this repo.
2. Create a branch (something like `yourname/homepage-refresh`).
3. Commit as you go.
4. Open a pull request against this repo's `main` branch and fill in the template.
5. Send us the PR link using the email address in your invite.
